Data types
	Primitive Types: Basic types like number, string, boolean, null, undefined, and symbol.
	Object Types: Complex structures including arrays, classes, interfaces, and functions.
	Primitive types are the most basic data types in TypeScript. They represent simple, immutable values and are directly assigned.
	Object types are more complex structures that can contain multiple values and functions. They are mutable and can be manipulated after creation.

Union Types and Intersection types
	Union: A union type represents a value that can be one of several types. You can create a union type by using the pipe (|) symbol between the types.
			type MyType = string | number;
			let value: MyType;
			value = "Hello"; // Valid
			value = 42;      // Valid
			value = true;    // Error: Type 'boolean' is not assignable to type 'string | number'.
	Intersection: An intersection type combines multiple types into one. A value of an intersection type must satisfy all the combined types. You can create an intersection type by using the ampersand (&) symbol between the types.
			type A = { name: string };
			type B = { age: number };
			type C = A & B;
			let person: C = {
				name: "Alice",
				age: 30
			};

	Example: Intersection
			interface Nameable {
				name: string;
			}
			interface Ageable {
				age: number;
			}
			type Person = Nameable & Ageable;
			const person: Person = {
				name: "Bob",
				age: 25
			};



Diff bet == an ===
	In JavaScript and TypeScript, == and === are comparison operators, but they differ in how they compare values.
	== (Equality)
	The == operator checks for equality between two values, but it performs type coercion if the values are of different types. Type coercion means that JavaScript tries to convert the values to the same type before making the comparison.	
			console.log(5 == "5");  // Output: true
			console.log(false == 0);  // Output: true
			console.log(null == undefined);  // Output: true

	In the above examples, JavaScript converts the string "5" to the number 5, false to 0, and null to undefined before comparing.
	=== (Strict Equality)
	The === operator checks for equality between two values without performing type coercion. This means that both the value and the type must be the same for the comparison to return true.
			console.log(5 === "5");  // Output: false
			console.log(false === 0);  // Output: false
			console.log(null === undefined);  // Output: false

	When to Use Which
	Use === (strict equality) to avoid unexpected behavior due to type coercion. It ensures that both the value and the type are exactly the same.
	Use == (equality) if you specifically want to allow type coercion.
	In general, it's recommended to use === for most comparisons to prevent potential bugs caused by type coercion.		

	
Implicit Type Coercion in javascript.
	Implicit type coercion in javascript is the automatic conversion of value from one data type to another. It takes place when the operands of an expression are of different data types.
	String coercion
	String coercion takes place while using the ‘ + ‘ operator. When a number is added to a string, the number type is always converted to the string type.
	Example 1:
			var x = 3;
			var y = "3";
			x + y // Returns "33

Explicit Type Coercion
	Explicit type coercion, or type casting, occurs when you manually convert a value from one type to another using built-in functions or constructors. This is a more controlled way of converting types because it avoids unexpected behaviors caused by implicit coercion.			
		String to Number:
			let str = "123";
			let num = Number(str); // Explicitly converts string to number
			console.log(num);  // Output: 123
		Number to String:
			let num = 123;
			let str = String(num); // Explicitly converts number to string
			console.log(str);  // Output: "123"

What is weakmap in javascript

What is set in JavaScript?

	A Set is a collection of values where each value must be unique. It can hold any type of values, whether primitive or object references. 
	Set maintains the insertion order of the elements and provides various methods to manipulate and iterate over its elements.

			let mySet = new Set();

			mySet.add(1);
			mySet.add(5);
			mySet.add(5); // Duplicate value, ignored
			mySet.add('some text');
			mySet.add({ a: 1, b: 2 });

			console.log(mySet.size); // Output: 4

				console.log(value);

What is weakset?

	A WeakSet is a collection of objects where the objects are held weakly, meaning that 
	if there are no other references to an object stored in the WeakSet, the object can be garbage collected.
	let weakSet = new WeakSet();

			let obj1 = { a: 1 };
			let obj2 = { b: 2 };

			weakSet.add(obj1);
			weakSet.add(obj2);

			console.log(weakSet.has(obj1)); // Output: true

			obj1 = null; // obj1 is now eligible for garbage collection

			// After garbage collection, obj1 will be removed from the WeakSet
			console.log(weakSet.has(obj1)); // Output: false (after garbage collection)


	Set:

	Stores unique values of any type.
	Maintains insertion order.
	Is iterable and provides methods like add, delete, has, and forEach.

	WeakSet:

	Stores unique object references only.
	Holds weak references, allowing garbage collection of unreferenced objects.
	Not iterable and does not provide methods to list its elements.

TypeScript - Abstract Class
	Define an abstract class in Typescript using the abstract keyword. Abstract classes are mainly for inheritance where other 
	classes may derive from them. We cannot create an instance of an abstract class.

	An abstract class typically includes one or more abstract methods or property declarations.
	The class which extends the abstract class must define all the abstract methods.

	Example 1: 
			abstract class Person {
				name: string;
				
				constructor(name: string) {
					this.name = name;
				}

				display(): void{
					console.log(this.name);
				}

				abstract find(string): Person;
			}

			class Employee extends Person { 
				empCode: number;
				
				constructor(name: string, code: number) { 
					super(name); // must call super()
					this.empCode = code;
				}

				find(name:string): Person { 
					// execute AJAX request to find an employee from a db
					return new Employee(name, 1);
				}
			}

			let emp: Person = new Employee("James", 100);
			emp.display(); //James
			let emp2: Person = emp.find('Steve');


	Example 2: 
			abstract class Person {
				abstract name: string;

				display(): void{
					console.log(this.name);
				}
			}

			class Employee extends Person { 
				name: string;
				empCode: number;
				
				constructor(name: string, code: number) { 
					super(); // must call super()
					
					this.empCode = code;
					this.name = name;
				}
			}

			let emp: Person = new Employee("James", 100);
			emp.display(); //James

What is application of type and interface
	In TypeScript, both type aliases and interfaces are used to define custom types. They have some similarities but also key differences and best use cases. Here’s an overview of their applications and when to use each:
	{ Type Aliases }
	A type alias is used to create a new name for a type. It can be used for primitive types, union types, intersection types, and more. Type aliases are flexible and versatile.
	Union and Intersection Types:
			type ID = string | number;
			type NameOrAge = { name: string } & { age: number };

	Primitive Types:
			type StringAlias = string;
	Function Types:
			type Callback = (error: Error | null, response: string) => void;
	Utility Types (using mapped types):
			type ReadOnly<T> = {
				readonly [P in keyof T]: T[P];
			};
	{ Interface }
	An interface is used to define the structure of an object. It is more suited for describing the shape of objects, including properties and methods. Interfaces can be extended and implemented by classes.
	Object Types:
			interface Person {
				name: string;
				age: number;
				location?: string;
			}
	Extending Interfaces:
			interface Employee extends Person {
				employeeId: number;
			}
			
	Implementing Classes:
			class Developer implements Person {
				name: string;
				age: number;
				location?: string;
			
				constructor(name: string, age: number, location?: string) {
					this.name = name;
					this.age = age;
					this.location = location;
				}
			}

		Describing Function Signatures:

			interface SearchFunction {
				(source: string, subString: string): boolean;
			}
			let mySearch: SearchFunction;
			mySearch = function (src, sub) {
				return src.includes(sub);
			};

	Key Differences and Best Practices
	Extensibility:
		Interfaces are more extensible. You can easily extend an existing interface by declaring it again.
		Type aliases are not as easily extendable. To extend a type alias, you need to create a new type.
	Union and Intersection Types:
		Use type aliases when you need to create union or intersection types, as interfaces do not support these directly.
	Object-Oriented Design:
		Use interfaces when you need to describe the shape of objects or define contracts for classes to implement.
	Complex Types:
		Use type aliases for more complex type definitions, such as unions, intersections, and mapped types.

	Basic Mapped Types
	Here's a simple example of a mapped type that makes all properties in a type readonly:
			type ReadOnly<T> = {
				readonly [P in keyof T]: T[P];
			};
			interface Person {
				name: string;
				age: number;
			}
			type ReadOnlyPerson = ReadOnly<Person>;
	In this example:
	ReadOnly<T> is a mapped type that takes a type T.
	[P in keyof T] iterates over each property P in the type T.
	readonly makes each property P in the resulting type readonly.
	T[P] keeps the original type of each property.
	The resulting ReadOnlyPerson type will be:
			interface ReadOnlyPerson {
				readonly name: string;
				readonly age: number;
			}

	Built-in Utility Types
	TypeScript provides several built-in utility types that use mapped types:
	Partial<T>: Makes all properties in T optional.
	Required<T>: Makes all properties in T required.
	Readonly<T>: Makes all properties in T readonly.
	Pick<T, K>: Creates a type with a subset of properties K from type T.
	Omit<T, K>: Creates a type by omitting properties K from type T.
			interface Person {
				name: string;
				age: number;
				location?: string;
			}
			type PartialPerson = Partial<Person>;
			type RequiredPerson = Required<Person>;
			type ReadOnlyPerson = Readonly<Person>;
			type NameAndAge = Pick<Person, 'name' | 'age'>;
			type PersonWithoutLocation = Omit<Person, 'location'>;
